# Codex integration in Duet 0.2.1

Duet uses the locally installed `codex app-server` over JSON-RPC. Authentication,
subscription limits and token refresh belong to that CLI. These features do not
require an API key or a separate API billing account.

The implementation was checked against `codex-cli 0.164.0-alpha.11.1`, including
TypeScript and JSON schemas generated by that exact executable. The protocol
reference is the [official app-server documentation](https://learn.chatgpt.com/docs/app-server).
Some server capabilities depend on the installed CLI version, account and feature flags;
Duet displays server errors instead of silently converting an unsupported operation into a prompt.

## Available workflows

| Area | Behavior |
| --- | --- |
| Conversations | Start, resume, stream, interrupt, steer, queue, fork and rewind; keep the same logical chat when changing providers. |
| Models | Discover available models, supported reasoning efforts and service tiers; clamp sent effort to the model's supported values. |
| Permissions | Default, edit, auto-review, read-only plan and explicit bypass modes. Scoped network/file permissions, command/edit approvals and older approval formats use the shared broker. |
| Questions | Blocking questions preserve IDs, secret fields and commas in answers. Asynchronous questions have a separate reply form. |
| MCP | List servers and tools, reload, open OAuth login, handle URL and typed form elicitation. Validate required fields, types and constraints in Rust before replying. |
| Skills | Discover skills, insert explicit `$skill-name` input, pass native skill references, enable or disable individual skills. |
| Review | Review uncommitted changes, a base branch, a commit or custom instructions. Findings render as Markdown with file links. |
| Context | Native manual compaction and context usage, plus [selective archive/compression/restore](CONTEXT_MANAGEMENT.md) through native scoped tools. Projection changes rebind the internal session while retaining the application chat and MCP team. Completion tracking distinguishes outer review turns from worker turns and ignores duplicate completion notifications. |
| Goals | Read, explicitly set, pause, resume or clear a goal; show native token usage and budget. Setting a goal is a user action, not inferred from an ordinary message. |
| Connections and hooks | Read available app connections, open their installation pages and inspect discovered hooks. Render hook execution progress. |
| Results | Plans, reasoning, command output, patch progress, MCP progress, web source links, saved generated images and subagent transcripts. |

The Codex controls button is in the chat header. Supported local commands:
`/status`, `/help`, `/model [id]`, `/permissions [mode]`, `/compact`,
`/review [instructions]`, `/mcp`, `/skills`, `/goal [objective|pause|resume|clear]`,
`/diff`, `/fork`, `/new`, `/clear`. These commands act on Duet or app-server;
they are not sent verbatim to the model. Unrecognized commands remain ordinary input.

## Mid-turn messages (0.2.3)

Main-chat follow-ups appear immediately while thinking continues. Each message has
its own UUID and transport receipt; unrelated model steps do not confirm delivery.
Accepted input is distinguished from input recorded in the agent context. Failures
remain visible with retry and do not close the active session.

First-send preparation and native sends preserve order. Initialized follow-ups do
not wait behind settings/review control requests. Codex uses
[`turn/steer`](https://learn.chatgpt.com/docs/app-server) and its accepted turn ID;
a definite no-active-turn rejection can start a successor in the same chat.
Late notifications from retired turns cannot finish that successor. Delivery does
not forcibly interrupt the provider's ongoing generation.

Verification includes native CLI fixtures on Windows/Linux, first-send and receipt
state regressions, WebView2 visibility/retry/collapsed-history checks, and an opt-in
real subscription smoke (`scripts/smoke-native-steering.mjs`) for Claude and Codex.

## Markdown links

Website and mail links use the system opener. File links resolve against the chat
that produced the message, including split view and subagent transcripts. Supported
forms include relative paths, Windows drive paths, UNC paths, POSIX absolute paths,
`file:` URLs, URI-encoded spaces/Unicode, `:line[:column]` and `#Lstart-Lend`.
The editor selects the requested position/range. Heading anchors scroll within
their own rendered message, with stable suffixes for duplicate headings.

Local raster images load lazily through the bounded native attachment reader.
Executable URL schemes are rejected. Middle clicks cannot navigate the app WebView
away from its UI. Link-open failures are visible to the user.

## Verification

- Windows WebView2: Markdown clicks, split-chat directory ownership, editor line and
  column, website routing, anchors, lazy local images, typed MCP form submission and
  the Codex MCP catalog. The same suite covers native services, window controls,
  shutdown and a 200-agent/10,000-event synthetic UI load.
- Linux WebKitGTK: native services and Markdown file links reaching the requested editor line.
- Rust unit tests: permissions, typed schemas, question answers, plan/review/question
  translation, duplicate completion and review worker-turn regressions.
- Isolated CLI fixtures: four-provider sessions, close/resume, permissions, MCP
  discovery/OAuth contracts, typed forms, questions, goals, review, compaction,
  skill inputs/configuration, app and hook catalogs, delegation and cleanup.
- Real signed-in Codex: two successive turns, manual compaction, native review,
  close/resume with original context retained; read-only plan mode.

OAuth browser completion, Windows sandbox installation, native goal execution,
real skill configuration changes and account-specific app connections were not
performed on the user's account as part of the tests. Their protocol contracts
are covered by isolated fixtures where applicable.

## Scope

This implements local coding workflows exposed by app-server. It does not reproduce
the proprietary Codex desktop/cloud application. Realtime audio sessions, host
attestation, external authentication-token ownership and experimental plugin
installation APIs are not implemented. Existing Duet voice input remains independent.
The official documentation marks plugin installation APIs as under development;
Duet does not present them as stable features.

All 121 Duet application commands are handled in Rust. No persistent Node core or
JavaScript Codex SDK adapter is introduced by this integration.
